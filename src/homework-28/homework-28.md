 Задача №2
 
  1.Обновился ли интерфейс автоматически?
   ( Да, во всех сценариях )

  2.Сколько раз выполнился ngDoCheck()?
   (
     1-й сценарий один раз при клике.
     2-й сценарий два раза, при клике и после setTimeout.
     3-й сценарий один раз, из-за объединения синхронного события клика и микрозадачи Promise.
     4-й сценарий три раза, при клике, при http запросе и получения ответа от сервира.
     5-й сценарий один при клике, и после по 1 на каждый запуск setInterval.
     6-й сценарий два раза, при клике обединяться в оду синхронную операцию Click и Promise, после выполнится setTimeout.
   )

  3.Понадобилось ли использовать ChangeDetectorRef?
   ( Нет )

  4.Что именно, по вашему мнению, стало причиной запуска Change Detection?

    Причиной запуска Change Detection является библиотека Zone.js. Она перехватывает асинхронные события (события DOM, таймеры, Promise, HTTP-запросы)
    и дает сигнал Angular о завершении асинхронной задачи, после чего Angular запускает проверку компонента


Задача №3

 Часть 1. markForCheck()

 1. Что произошло после markForCheck()?

    Компонент был помечен как требующий проверки при следующем проходе CD.

 2. Обновился ли интерфейс сразу?

    Нет, markForCheck() не означает немедленный запуск проверки, он только помечает компонент для проверки при следующем проходе CD.

 3. Когда фактически произошёл CD?

    При следующем запуске CD Angular проверяет помеченный компонент

 4. Почему без markForCheck() интерфейс не обновлялся?

    Потому что при OnPush Angular не проверяет компонент при каждом общем цикле CD.


Часть 2. detectChanges()

 1. Чем поведение отличается от предыдущего сценария?

    Отличия detectChanges() в том что он вызывает проверку сразу не ожидая следующего запуска CD

 2. Выполняется ли Change Detection немедленно?
    ( Да )

 3. Какие компоненты были проверены?

    Это локальная ручная проверка, при вызове detectChanges() проверится только компонент change-detection-onpush (и его дочерние компоненты) 

 4. В каких случаях использование detectChanges() предпочтительнее?

    Если нужна немедленная локальная проверка, либо если нужно обновлять конкретное поддерево, не ожидая следующего общего цикла CD

Часть 3. detach()

 1. Обновляется ли интерфейс?
    ( Нет )

 2. Выполняется ли ngDoCheck()?
    ( Нет )

 3. Почему Angular перестал проверять компонент?

    Потому что отсоединил его view от дерева CD

 4. Какие способы изменения значения больше не работают?

    Сами способы изменения значения продолжают работать, не работает отражение этих изменений в DOM через обычный CD

Часть 4. reattach()

 1. Что изменилось после reattach()?

    После вызова reattach() компонент снова подключился к дереву CD

 2. Когда компонент снова начал участвовать в Change Detection?

    Компонент снова начал участвовать после вызова reattach(), но сама проверка произошла при следующем цикле CD

 3. Нужно ли дополнительно вызывать detectChanges() или markForCheck()?

    Нет, После reattach() компонент снова участвует в обычном CD. Поэтому при следующем подходящем цикле Angular сможет его проверить
